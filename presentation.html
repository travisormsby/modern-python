1 - Managing environments

Problem

You wrote a script for other people.

It uses tomllib, introduced in Python 3.11.

It uses GeoPandas, which is not included in the default ArcGIS Pro Python environment.

How do you make sure they can run it?

requirements.txt is bad

  • pip is slow
  • Easy to accidentally corrupt system Python
  • Easy to forget to update it
  • Non-determinative
  • Useless for specifying a Python version
  • Useless for non-Python dependencies

environment.yml is bad

  • conda makes pip look fast.
  • Environments are buried in esoteric locations
  • It usually fails if using ArcGIS Pro’s conda

uv is better

Pros

  • Fast
  • Simpler to use
  • lock file guarantees environment duplication
  • Can include dependencies in the script (PEP 723)

Cons

  • Useless for non-Python dependencies
  • Ecosystem risk from OpenAI acquisition

pixi is even better for geospatial

Pros

  • Can handle non-Python dependencies
  • As fast as uv for Python dependencies
  • Faster than conda for non-Python dependencies

Cons

  • Not as easy to use as uv
  • Can’t use PEP 723 script metadata

Exercise 1: Use uv and pixi to manage environments

  • pyproject.toml ensures environment is always documented
  • Lock file ensures versions are always pinned
  • Storing environments with projects improves discoverability
  • Caching packages improves efficiency

2 - Creating dynamic text

Problem

Your code needs to make a string like:

"A Canada lynx was sighted at 48.8° N, 93.2° W"

You have these variables whose values aren’t known until runtime:

  • species
  • lat
  • lon

How do you do it?

C-style formatting is bad

species = "Canada lynx"
lat = 48.8
lon = 93.2

output = "A %s was sighted at %d° N, %d° W" % (species, lat, lon)
print(output)
A Canada lynx was sighted at 48° N, 93° W
A Canada lynx was sighted at 48° N, 93° W
  • Arcane syntax
  • Values separated from place in string

String format method is bad

output = "A {} was sighted at {}° N, {}° W".format(species, lat, lon)
print(output)
A Canada lynx was sighted at 48.8° N, 93.2° W
  • Values still separated from place in string

f-strings are better

output = f"A {species} was sighted at {lat}° N, {lon}° W"
print(output)
A Canada lynx was sighted at 48.8° N, 93.2° W
  • Values are in the right location in the string
  • Well-named variables make the string readable

f-strings have a security problem

This code retrieves some information given a user name

from sqlalchemy import create_engine, text


def print_secrets(name):
    engine = create_engine("sqlite:///data/example.db")
    with engine.connect() as conn:
        stmt = text(f"SELECT secret FROM users WHERE name = '{name}'")
        rows = conn.execute(stmt).fetchall()
        if rows:
            for row in rows:
                print(*row)
        else:
            print("No records returned")

f-strings have a security problem

normal_name = "Alice"
print_secrets(normal_name)
Alice secret info
malicious_name = "' OR 1=1; -- "
print_secrets(malicious_name)
Alice secret info
Bob secret info
Carol secret info

t-strings are better for security

# from sqlalchemy import create_engine, text
from sqlalchemy import create_engine, tstring


def print_secrets(name):
    engine = create_engine("sqlite:///data/example.db")
    with engine.connect() as conn:
        # stmt = text(f"SELECT secret FROM users WHERE name = '{name}'")
        stmt = tstring(t"SELECT secret FROM users WHERE name = {name}")
        rows = conn.execute(stmt).fetchall()
        if rows:
            for row in rows:
                print(*row)
        else:
            print("No records returned")

t-strings are better for security

print_secrets(normal_name)
Alice secret info
print_secrets(malicious_name)
No records returned

t-strings are worse for most dynamic strings

output = t"A {species} was sighted at {lat}° N, {lon}° W"
print(output)
Template(strings=('A ', ' was sighted at ', '° N, ', '° W'), interpolations=(Interpolation('Canada lynx', 'species', None, ''), Interpolation(48.8, 'lat', None, ''), Interpolation(93.2, 'lon', None, '')))

Exercise 2: Use f-strings and t-strings to create dynamic text

  • You can use any expression, not just variable names
  • Formatting values uses its own a mini-language
  • Don’t mix and match strategies for creating dynamic text
  • t-strings are useless without a tag function

3 - Manipulating filepaths

Problem

You have a web service that gets data from a set of partitioned GeoParquet files

The service URL should be based on the filepath needed for that query. For example:

  • Filepath: /data/country=Bangladesh/year=1997/buildings.parquet
  • URL: https://api.example.com/buildings?country=Bangladesh&year=1997

How do you get the right URL given a filepath?

String methods are bad

from urllib.parse import urlencode

filepath = "/data/country=Bangladesh/year=1997/buildings.parquet"
parts = filepath.split("/")
file_name = parts[-1]
file_stem = file_name.replace(".parquet", "")
params = dict(p.split("=") for p in parts if "=" in p)
query_string = urlencode(params)
url = f"https://api.example.com/{file_stem}?{query_string}"
print(url)
https://api.example.com/buildings?country=Bangladesh&year=1997
  • A path is not a string - its structure carries meaning
  • Why is split used on line 4?
  • Why is list indexing used on line 5?
  • Why is replace used on line 6?
  • Why is split used again on line 7?

os.path is only a little better

import os
from urllib.parse import urlencode

filepath = "/data/country=Bangladesh/year=1997/buildings.parquet"
parts = os.path.normpath(filepath).split(os.sep)
file_name = parts[-1]
file_stem = os.path.splitext(file_name)[0]
params = dict(p.split("=") for p in parts if "=" in p)
query_string = urlencode(params)
url = f"https://api.example.com/{file_stem}?{query_string}"
print(url)
https://api.example.com/buildings?country=Bangladesh&year=1997
  • Still fundamentally treats paths as strings, need comments to explain
  • normpath and os.sep have slightly better semantics

pathlib is much better

from pathlib import Path
from urllib.parse import urlencode

filepath = Path("/data/country=Bangladesh/year=1997/buildings.parquet")
params = dict(p.split("=") for p in filepath.parts if "=" in p)
query_string = urlencode(params)
url = f"https://api.example.com/{filepath.stem}?{query_string}"
print(url)
https://api.example.com/buildings?country=Bangladesh&year=1997
  • Treats paths as Path objects, not ordinary strings
  • Better names provide clear semantic meaning
    • filepath.parts instead of filepath.split("/")
    • filepath.stem instead of parts[-1].replace(".parquet", "")

Exercise 3: Use pathlib to manipulate filepaths

  • Good names make code more self-documenting
  • Separates abstract path manipulation from touching the filesystem
  • Convenient syntactic sugar for common tasks

4 - Structure data

Problem

You have an API for updating parcel values

The API expects a particular format:

correct = {"propertyId": "0123456789", "value": 251482.17}

You also have submissions like:

missing_field = {"value": 251482.17}
wrong_types = {"propertyId": 1234567890, "value": "324398.71"}
uncoercable = {
    "propertyId": ["0123456789", "1234567890"],
    "value": [251482.17, 324398.71],
}
  • Ensure the submission has the right keys and value types
  • Reject the submission only when impossible to parse

Manual validation is bad

for submission in (correct, missing_field, wrong_types, uncoercable):
    try:
        if type(submission["propertyId"]) in (str, int, float, bytes):
            property_id = str(submission["propertyId"])
        else:
            raise ValueError
        value = float(submission["value"])
        valid_submission = {"propertyID": property_id, "value": value}
        print(valid_submission)
    except KeyError:
        print("Missing required field")
    except ValueError:
        print("Improper data type")
{'propertyID': '0123456789', 'value': 251482.17}
Missing required field
{'propertyID': '1234567890', 'value': 324398.71}
Improper data type
  • The definition of a valid submission is buried
  • Writing the type checking is painful

Dataclasses are only a bit better

from dataclasses import dataclass


@dataclass
class ValidSubmission:
    propertyId: str
    value: float


for submission in (correct, missing_field, wrong_types, uncoercable):
    try:
        print(ValidSubmission(**submission))
    except TypeError:
        print("Error: Missing required field")
    except ValueError:
        print("Error: Improper data type")
ValidSubmission(propertyId='0123456789', value=251482.17)
Error: Missing required field
ValidSubmission(propertyId=1234567890, value='324398.71')
ValidSubmission(propertyId=['0123456789', '1234567890'], value=[251482.17, 324398.71])
  • Good that the valid submission definition is centered
  • Types are defined, but not actually checked at runtime

Pydantic (v2) models are best

from pydantic import BaseModel, ConfigDict, ValidationError


class ValidSubmission(BaseModel):
    propertyId: str
    value: float
    model_config = ConfigDict(coerce_numbers_to_str=True)


for submission in (correct, missing_field, wrong_types, uncoercable):
    try:
        print(ValidSubmission(**submission))
    except ValidationError as e:
        for error in e.errors():
            print(f"Error: {error['msg']}")
propertyId='0123456789' value=251482.17
Error: Field required
propertyId='1234567890' value=324398.71
Error: Input should be a valid string
Error: Input should be a valid number
  • Type enforcement (strictly so, sometimes annoyingly)
  • Free error messages

Exercise 4: Enforce a data contract with Pydantic models

  • Good representation of a single table row
  • Strict type checking
  • Convenient dot notation
  • Easy serialization to other formats
